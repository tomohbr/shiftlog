# シフトログ 画面と文章の決まり（2026-10-25）

Stripe のダッシュボードと Jira の画面を手本にしている。両方に共通するのは「面は白と細い線、色は1色、1画面に主役のボタンは1つ、状態は言葉で言い切る」。
新しい画面を作るとき、直すときは、まずここを読む。

## 1. 色

- アクセントは **青（blue-600）1色**。主役のボタン、選択中、リンクに使う。緑・紫・エメラルドを「目立たせたいから」で使わない
- 状態の色は意味を固定する。緑＝完了・公開中、黄（amber）＝注意・未完了、赤＝失敗・削除だけ。飾りに使わない
- 面は白、背景は gray-50、区切りは gray-200 の線。グラデーションは使わない
- 影（shadow-xl 等）で浮かせるのは **モーダルだけ**。ページのカードは `card`（細い線＋shadow-sm）

## 2. 部品（index.css にある）

| クラス | 使いどころ |
|---|---|
| `btn-primary` | その画面の主役。1画面に1つ |
| `btn-secondary` | それ以外の操作（白＋線） |
| `btn-ghost` | 文字だけの補助リンク |
| `btn-danger` | 削除・解除。確認ダイアログとセット |
| `card` | 内容のまとまり |
| `auth-shell` / `auth-card` | ログイン・登録・初期設定など、サイドバーの無い全画面 |
| `input-field` | 入力欄。ラベルは上に `text-sm font-medium` |
| `eyebrow` | セクションの小見出し（gray-500・太字・小さめ） |
| `page-title` | ページ名 |

- アイコンは **Lucide** だけ（`lucide-react`）。絵文字は使わない（端末で見た目が変わり、安っぽく見える）
- 時刻・金額・件数は `tabular-nums`（表の桁が揃う）

## 3. 状態を言い切る

「公開中」「まだスタッフに見えていません」のように、**いま何が起きているか**を名詞で止めず文で書く。
ボタンは「何が起きるか」が分かる動詞にする（「公開」ではなく「スタッフに公開する」）。
空の状態には、次にやる1つの操作だけを置く（`components/PublicationBar.tsx` が例）。

## 4. 文章

- です・ます。感嘆符「！」は使わない（通知・トーストも同じ）
- 同じ入力を二度求めない（登録画面の店舗名 → 初期設定でまた店舗名、は離脱を生んだ）
- 画面の約束は実態と一致させる（「デモ店舗ですぐ確認」と書いて無いのは不可）
- 用語は固定する: **店舗**（施設）／**スタッフ**（人）／**打刻**（行為）／**タイムカード**（記録の画面）／**公開**（スタッフに見せる）／**希望シフト**（スタッフの提出）／**管理者**（権限名。画面では「オーナー・店長」）
  - 例外: クリスマスマーケットなど複数拠点の運用画面（希望から自動作成・会場枠）では「会場」を使う。一般画面（シフト追加・今日の状況・絞り込み）の「会場」は 2026-10-25 時点で未統一。切り替えるなら本人の判断で一括に
- トーストは「何をしたか」を1文で。失敗は「もう一度」など次の動作を添える

## 5. スマホ

- スタッフ向けはまず 375px で開いて見る。一番知りたいこと（次はいつ・どこ・誰と）を一番大きく
- 横に長い表は表だけ横スクロール、ページは横に動かさない
- タップ領域は 44px 以上。文字は 12px 未満にしない（補足でも 11px まで）

## 6. 手本にした具体的な点

- Stripe: 左ナビ＋白い面、青1色、数字は等幅、余白で区切る、成功は緑のバッジで言い切る
- Jira: ページ名を常に上に、空の状態に1つのCTA、一覧は線で区切る（カードを並べない）
